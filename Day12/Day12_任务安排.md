## 一、分治思想是什么？

分治法把一个大问题拆成若干个小问题，分别解决后再合并结果。三步走：

```
1. 分（Divide）   → 把原问题拆成多个相同结构的子问题
2. 治（Conquer）  → 递归地解决每个子问题
3. 合（Combine）  → 把子问题的解合并成原问题的解
```

今天学的三个算法都是分治思想的体现，但"合"这一步各有不同。

## 二、二分查找（Binary Search）

### 核心思想

在**有序**数组中查找目标值，每次对半砍：

```
[1, 3, 5, 7, 9, 11, 13]  找 7
         ↑
    中间是 7 → 找到了！

[1, 3, 5, 7, 9, 11, 13]  找 5
         ↑
    中间是 7，5 < 7 → 只搜左半边 [1, 3, 5]
         ↑
    中间是 3，5 > 3 → 只搜右半边 [5]
         ↑
    找到了！
```

### 关键点
- **前提**：数组必须有序
- **时间复杂度**：O(log n) —— 每次砍半，16 个元素最多 4 次，100 万个元素最多 20 次
- **边界陷阱**：while 条件是 `left <= right` 还是 `left < right`？mid 怎么算不溢出？
- **两种写法**：while 循环版（简单直观）和递归版（理解分治）

### 任务
1. 实现 `binary_search(arr, target)` → 返回索引，找不到返回 -1
2. 实现 `binary_search_recursive(arr, target, left, right)` → 递归版
3. 思考：如果数组有重复元素，要找第一个出现的位置怎么办？

## 三、快速排序（Quick Sort）

### 核心思想

选一个基准值（pivot），把数组分成两堆——小的放左边，大的放右边，再递归排两边。

```
[5, 3, 8, 1, 9, 2]  选最后一个 2 做 pivot
         ↓ partition
[1, 2, 8, 5, 9, 3]  2 归位到索引 1
 ← ← pivot → → → →

再递归排 [1] 和 [8, 5, 9, 3]
```

### 关键点
- **核心操作**：`partition` —— 把 pivot 放到正确位置，并返回它的索引
- **时间复杂度**：平均 O(n log n)，最坏 O(n²)（数组已有序且 pivot 总选最左/最右时）
- **空间复杂度**：O(log n)（递归调用栈）
- **稳定性**：❌ 不稳定（partition 过程中相同元素的相对位置可能改变）
- **原地排序**：✅ 不需要额外数组

### 任务
1. 实现 `partition(arr, low, high)` → 返回 pivot 最终位置
2. 实现 `quick_sort(arr, low, high)` → 递归排序
3. 思考：怎么避免最坏情况？随机选 pivot 有用吗？

## 四、归并排序（Merge Sort）

### 核心思想

先把数组从中间切开，分别排好序，再把两个有序数组合并成一个。

```
[5, 3, 8, 1, 9, 2]
        ↓ 分
[5, 3, 8]    [1, 9, 2]
   ↓ 分         ↓ 分
[5] [3, 8]   [1] [9, 2]
    ↓ 分          ↓ 分
[5] [3] [8]  [1] [9] [2]
    ↓ 合         ↓ 合
[5] [3, 8]   [1] [2, 9]
   ↓ 合         ↓ 合
[3, 5, 8]    [1, 2, 9]
        ↓ 合
[1, 2, 3, 5, 8, 9]
```

### 关键点
- **三步完整走**：分（split）→ 治（递归排序）→ 合（merge 两个有序数组）
- **时间复杂度**：始终 O(n log n)，最好最坏都一样
- **空间复杂度**：O(n)（需要临时数组存放合并结果）
- **稳定性**：✅ 稳定（merge 时相等元素保持原顺序）

### 任务
1. 实现 `merge(left, right)` → 合并两个有序数组
2. 实现 `merge_sort(arr)` → 递归排序
3. 思考：为什么归并排序在任何情况下都是 O(n log n)？

## 五、快排 vs 归并 对比

| 维度 | 快速排序 | 归并排序 |
|------|----------|----------|
| 时间复杂度（平均） | O(n log n) | O(n log n) |
| 时间复杂度（最坏） | O(n²) | O(n log n) |
| 空间复杂度 | O(log n) | O(n) |
| 稳定性 | ❌ 不稳定 | ✅ 稳定 |
| 原地排序 | ✅ 是 | ❌ 需要额外空间 |
| 适合场景 | 内存紧张，追求平均速度 | 需要稳定，链表排序 |
